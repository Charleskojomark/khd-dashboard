### Concurrency Patterns (Critical - Saleor runs concurrently)

**Atomic Increment - use F() expressions:**
```python
from django.db.models import F
Model.objects.filter(pk=pk).update(count=F("count") + 1)
```
Never: `instance.count += 1; instance.save()` (NOT atomic)

**Avoid Check-Then-Act - use update_or_create:**
```python
obj, created = Model.objects.update_or_create(
    app=app, key=key,  # Lookup fields (must have unique constraint)
    defaults={"field": value}  # Fields to update
)
```

**Row-Level Locking - use select_for_update:**
```python
from saleor.core.tracing import traced_atomic_transaction

with traced_atomic_transaction():
    obj = Model.objects.select_for_update().get(pk=pk)
    # Row locked until transaction ends
```

**Pattern: Create lock_objects.py modules** (see `saleor/payment/lock_objects.py`):
```python
def my_model_qs_select_for_update() -> QuerySet[MyModel]:

```

**Structure:**
1. Task file: `saleor/<app>/migrations/tasks/saleor<version>.py`
2. Migration file: `saleor/<app>/migrations/<number>_<name>.py`

**Task rules:**
- Decorate with `@app.task(queue=settings.DATA_MIGRATIONS_TASKS_QUEUE_NAME)` and `@allow_writer()`
- Process in batches (e.g. 1000 rows)
- Use `select_for_update` via app's `lock_objects` module
- Use subquery pattern: lock rows first, then filter+update
- Self-chain with `.delay()` if more rows exist

**Migration rules:**
- Use `post_migrate` signal (not inline)

- Always provide `migrations.RunPython.noop` as reverse

**Reference:** `saleor/giftcard/migrations/tasks/saleor3_22.py` and `saleor/giftcard/migrations/0023_mark_gift_cards_search_vector_as_dirty.py`
